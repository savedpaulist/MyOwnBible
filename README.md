# BibleOWN

## Сборки приложения и логотип

Изумрудный логотип хранится в `resources/branding` и подключён к сборкам:

- обычный `cargo build` на Windows встраивает `windows/mob.ico` в `.exe` как
  ресурс с ID `1`; этот же ресурс GPUI использует для окна и панели задач;
- для macOS `cargo bundle --release` создаёт `.app` с `macos/mob.icns`;
- `mob-logo-master-1024.png` остаётся мастер-файлом для магазинов и будущих
  форматов упаковки.

Для создания macOS-пакета один раз установите упаковщик и запускайте команду
на Mac:

```sh
cargo install cargo-bundle
cargo bundle --release
```

Для универсальной macOS-сборки Intel + Apple Silicon:

```sh
cargo bundle --release \
  --target x86_64-apple-darwin \
  --target aarch64-apple-darwin
```

## Синхронизация и перенос данных

В разделе «Настройки → Синхронизация» можно подключить свой Google Drive. BibleOWN
отправляет изменения напрямую в служебную папку приложения на диске пользователя.
Модули, индексы, настройки интерфейса и открытые вкладки хранятся на устройстве.
Проекты Google Cloud и аккаунты образуют отдельные хранилища. Для обмена на двух
устройствах используйте один проект OAuth и один аккаунт Google.

### Подготовка сборки с входом через Google

1. В [Google Cloud Console](https://console.cloud.google.com/apis/library/drive.googleapis.com)
   создайте проект и включите Google Drive API.
2. В **Google Auth Platform** настройте **Branding** и **Audience**. Для пробного
   подключения в режиме **Testing** добавьте свой Google-аккаунт в тестовые
   пользователи.
3. В **Clients** создайте один OAuth-клиент типа **Desktop app** для всех
   устанавливаемых копий приложения. Скопируйте Client ID. Client secret для
   desktop-приложения не является конфиденциальным и в этой реализации
   необязателен благодаря PKCE. [Инструкция Google](https://developers.google.com/identity/protocols/oauth2/native-app)
4. Передайте Client ID как переменную окружения при сборке. Он будет встроен в
   бинарник, поэтому пользователю на новом устройстве не потребуется JSON-файл.
   Пример для macOS и Linux:

   ```sh
   BIBLEOWN_GOOGLE_CLIENT_ID='ваш-client-id.apps.googleusercontent.com' cargo build --release
   ```

   PowerShell:

   ```powershell
   $env:BIBLEOWN_GOOGLE_CLIENT_ID = 'ваш-client-id.apps.googleusercontent.com'
   cargo build --release
   ```

   Если конкретный OAuth-клиент требует Client secret, его по-прежнему можно
   передать через `BIBLEOWN_GOOGLE_CLIENT_SECRET`, но считать его секретом внутри
   распространяемого desktop-бинарника нельзя.

Для закрытого теста оставьте Audience в режиме **Testing** и добавьте тестовые
аккаунты. Учтите, что выданные в этом режиме разрешения, включая refresh token,
истекают через 7 дней. Для длительного бета-теста переведите External-приложение
в **In production**, заполните Branding, домашнюю страницу и политику
конфиденциальности. Используемый scope `drive.appdata` относится к
non-sensitive и даёт доступ только к скрытой папке данных этого приложения.

### Подключение в BibleOWN

В готовой сборке откройте «Настройки → Синхронизация» и нажмите
**«Подключить Google Drive»**. Выберите аккаунт в браузере, разрешите доступ и
вернитесь в BibleOWN. Статус сменится на **«Google Drive подключён»**, после
чего начнётся обмен данными. Для сборок без включённого клиента доступна кнопка
«OAuth-клиент…», которая принимает JSON для локальной разработки.

На Linux для Drive нужны
`curl`, `secret-tool` и работающая служба Secret Service. На Windows используется
системный `curl.exe` и диспетчер учётных данных, на macOS — системный `curl` и связка ключей.

**Экспортировать…** создаёт папку с `bibleown.json` и обычными Markdown-файлами
в подкаталоге `notes`. В JSON входят цепочки, вопросы, теги, пометки, личные комментарии,
параллельные места и, если имеются, версии записей из конфликтов. Экспорт хранится
в открытом виде. Markdown можно сразу открыть в другом редакторе. **Импортировать…**
принимает эту папку в BibleOWN и сохраняет разные версии совпадающих записей для
выбора. Экспорт и импорт работают через локальные файлы.
